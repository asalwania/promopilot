# The architecture document's module diagram shows the transitive reduction of the real imports, and a test checks it

#75 asks for an architecture overview a judge can trust. ADR 0088 already ties the agent-graph diagram to the compiled graph. The document also needs to show which module uses which, because "deep modules with small interfaces and no cross-module private imports" (CLAUDE.md) is a claim about the code, and a hand-drawn picture of it can drift. SPEC.md does not say how the picture is made or kept true.

## Decisions

- **The diagram is a hand-written Mermaid `flowchart` in `docs/architecture.md`, marked `%% module-dependencies`.** An arrow `a --> b` means module `a` imports module `b`.
- **It draws the transitive reduction, not every import.** The 18 modules import each other in about 70 ways, so a full graph is unreadable. An arrow is drawn only when the user does not already reach the used module through another module in the diagram. Every omitted dependency is therefore implied by the arrows.
- **Some modules are left out and the page says so.**
  - `domain`, `economics` and `config` are used by everyone.
  - `cassettes`, `demo` and `logs` are wiring and scripts.
  - `evals` is the offline harness that plays the whole stack, and it is drawn in the process flow.
  - With `evals` left out, `api --> agents` is not implied by anything, so the picture shows the API's real route into the planner.
- **`backend/tests/architecture/test_architecture_doc.py` checks it.** It parses every file under `backend/src/promopilot/` with `ast`, takes each module's absolute `promopilot.<module>` imports among the diagram's nodes, reduces them transitively and asserts the result equals the diagram's arrows. A new dependency, or a removed one, fails the test and names the missing and extra arrows.
- **We rejected two alternatives.** A diagram generated by a tool such as pydeps would show every import and no reasons. An unchecked picture would drift, as the README's old one did.

## Consequences

- A ticket that adds, removes or reroutes a dependency among the drawn modules updates the diagram. A dependency that another drawn module already implies changes nothing.
- The test only sees absolute `promopilot.*` imports. The package has no cross-module relative imports, and a private-name import is the job of the existing boundary tests.

## Also decided: the README repeats five headline numbers

ADR 0088 (D4, D5) said the README would link to `docs/nine-blocker.md` for the eval numbers instead of copying them. A judge reads the README first, so it now holds one five-row table (baseline, constraints, grounding, regret, consistency), each value a `<!-- LATE: -->` slot. `docs/nine-blocker.md` stays the source: the README's values are copied from the same published report, with its timestamp, and #81's submission check compares the two. The architecture document still quotes no eval number.

The README also lists the open follow-up issues as known gaps, so a reader meets them before they find them.
